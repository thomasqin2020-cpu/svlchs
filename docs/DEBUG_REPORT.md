## Headline: the homepage spiral "isn't working" — FIXED ✅

**Root cause (proven, not guessed):** the WebGL spiral shader renders and animates correctly
(`readPixels` showed peak brightness 765/765 and frame-to-frame change). It looked frozen/black only
because `.home-page .bg-spiral-veil` was too opaque (radial `0.32→0.62`, linear up to `0.42`) and
washed the spiral down to near-black. Isolation test: hiding just the veil made the spiral vivid;
restoring it blacked it out — so the veil was the single cause.

**Fix:** lightened the homepage veil to `radial 0.16→0.40`, `linear up to 0.30`
(`src/app/globals.css`, `.home-page .bg-spiral-veil`). Verified live on desktop and mobile — the
gold/blue arms now read clearly through the transparent hero while the title stays legible.
(The `/login` and `/signup` spirals were checked and already show through their heavier veil at most
animation phases, so they were left as-is.)

## Recommended next (deferred — product / architecture judgment or broader batches)

These are real, verified findings I did **not** auto-apply because they involve a product decision,
touch a not-yet-enabled flow, or are a larger a11y/SEO batch worth doing deliberately:

- **#8 `/donate/success` asserts the payment succeeded without verifying it.** It should become a
  Server Component that reads `session_id`/`pi`, retrieves the session/PaymentIntent via Stripe, and
  only shows success copy when `payment_status === 'paid'`. *(Honesty/correctness — recommended.)*
- **#9 / #25 Webhook can double-count or drop donations.** `checkout.session.completed` and
  `payment_intent.succeeded` upsert on different conflict keys; reconcile to one `payment_intent`-keyed
  row, and idempotently back-fill from `/donate/success` so a webhook outage doesn't lose a donation.
  *(Only bites once the monthly/subscription flow is enabled.)*
- **#10 Hardcoded fallback event dates (`2026-02-21`, `2026-03-21`) are already past**, so with no
  Supabase events the homepage advertises past dates as upcoming. Seed events in Supabase, or align the
  fallback/live date policy. *(Content — moot once the DB is seeded.)*
- **#11 / #16 Scroll-spy + dock nav assume the static section order**, so an admin section reorder/hide
  highlights the wrong pill / yields a dead link. Drive the spy and nav from the live layout.
- **#12 / #13 Form labels aren't associated with inputs** (auth, donate, and Stripe Elements fields):
  add `htmlFor`/`id` (use `useId()`), and `role="group" aria-labelledby` for the iframe card fields.
- **#29 Six `<h1>`s flatten the heading outline.** Keep the hero as the sole `<h1>`; demote the five
  per-section titles to `<h2>` (JSX-element-only — no CSS class changes).
- **#31 No per-route titles or OpenGraph/Twitter metadata** beyond root + `/donate`; add `metadataBase`
  + `openGraph`/`twitter` to root and a small `metadata` export per route.
- **#26 / #27 remainders:** validate `grade` server-side; add the email format check to the competition
  register action too.
